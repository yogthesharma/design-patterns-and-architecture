# Design Patterns and Architecture

Standalone learning repo. Work here on its own — no other repos required.

**Phase (for your own roadmap):** Backend

## Context

Code structure ages better when boundaries are intentional. SOLID, clean architecture, DDD ideas, and monolith vs microservices / event-driven shapes are studied here as design practice — not tied to one framework.

This repository is the single place for everything related to **Design Patterns and Architecture**: notes, exercises, and small projects. Clone it, open it, and treat it as a complete unit of study.

## Scope

- SOLID and common design patterns (with judgment, not cargo cult)
- Clean / hexagonal architecture boundaries
- Domain-Driven Design ideas that actually help
- Monolith vs microservices tradeoffs
- Event-driven architecture basics

## Outcomes

When you are done with this repo, you should be able to:

- Draw a clear module boundary for a non-trivial feature
- Argue monolith vs services with real criteria
- Apply a pattern only when it reduces complexity

## How to work in this repo

1. Read / write concept notes under `notes/`.
2. Solve practice problems under `exercises/`.
3. Ship at least one small project under `projects/` that forces the ideas to stick.
4. Tick the checklist below as you go.

You do not need any other curriculum repo open while you work here.
